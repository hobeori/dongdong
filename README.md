# 05-pjt · 댓글 증강 시스템

회사명을 입력하면 **토스증권 커뮤니티 댓글을 실시간 크롤링**하고, 전처리 → LLM 증강 → 요약까지
한 화면에 보여주는 Django 웹 서비스입니다. (Django + Selenium + SSAFY GMS LLM)

입력 → 크롤링 → 전처리 → 증강 → 출력의 흐름을 하나의 웹 서비스로 구현했고, 데이터는 사전에 저장하지 않고
요청 시점에 실시간으로 수집합니다(처리 결과만 DB에 기록).

## 1. 실행 방법

Python 3.10+ 와 Chrome이 필요합니다.

```bash
pip install -r requirements.txt
cp .env.example .env     # Windows: copy .env.example .env  → .env 를 열어 키 입력
python manage.py migrate
python manage.py runserver
```

`.env` 예시 (SSAFY GMS)

```
GMS_API_KEY=발급받은키
GMS_BASE_URL=https://gms.ssafy.io/gmsapi/api.openai.com/v1
MODEL=gpt-5-nano
```

http://127.0.0.1:8000/ 접속 → 회사명 입력(예: `삼성`).
디버깅 시 `CRAWL_HEADLESS=0`을 주면 크롤링 브라우저 창이 보입니다. 테스트: `python manage.py test`

원본 탭에서는 제거된 댓글이 흐리게 표시되고 제거 사유(규칙 / 부적절)가 붙습니다.

## 4. 프로젝트 구조

```
config/                 Django 설정 (.env 로딩, GMS/크롤링 옵션)
comments/
  models.py             CommentAnalysis (단계별 결과 저장)
  views.py              입력 검증 / 일반 응답 / 스트리밍(NDJSON) 응답
  services/
    crawler.py          Selenium 크롤러 (검색·스크롤·댓글 추출)
    preprocess.py       길이 필터·특수문자 제거·IQR 통계
    llm.py              GMS 호출 (부적절 필터링 / 증강 / 요약)
    pipeline.py         전체 흐름 (진행 이벤트를 yield)
  templates/comments/   index.html, _results.html
  tests/                14+ 단위·뷰 테스트 (크롤러·LLM은 mock)
```

설계 포인트
- `pipeline.run()` 제너레이터 하나가 일반 요청과 스트리밍 요청에서 재사용됩니다.
- 최종 결과 = 정제 댓글 + 증강 댓글. IQR 통계는 원본 길이 기준으로 계산해 저장하고, 실제 필터링은 명세의 5~76자를 씁니다.
- LLM 호출이 실패해도 크롤링 결과는 화면에 보여주고 경고만 표시합니다.

## 5. 겪은 문제와 해결

- **검색창이 안 열림**: 최초 접속 시 뜨는 안내 팝업이 클릭을 가로챘습니다 → 팝업을 먼저 닫고, 모달의 입력창을 직접 찾도록 수정.
- **검색 결과 대기 오류**: 홈 화면에도 종목 링크가 있어 대기 조건이 바로 통과됐습니다 → 입력창 기준으로 대기하고 Enter 후 URL 변화를 확인.
- **댓글이 비어 있음**: 클래스명이 난독화되어 있어 CSS 셀렉터가 불가능했습니다 → 화면 위치(정렬 버튼 아래, 주문 패널 왼쪽, 하단 바 위)와 텍스트 노드 기준으로 추출.
- **스크롤이 안 됨**: 페이지가 아니라 내부 영역이 스크롤됩니다 → 스크롤 가능한 요소를 찾아 화면 높이의 60%씩 내리며 댓글을 누적.
- **하단 시세 바·작성자명이 섞임**: 하단 바 위쪽까지만 피드로 보고, "n분 · 팔로워 n" 줄과 그 앞의 작성자명은 제외.
- **`no column named raw_status`**: 모델 변경 후 `migrate`를 하지 않아 발생 → 마이그레이션 적용.

## 6. 학습 내용

- Django의 URL → View → Template 흐름과 모델/마이그레이션으로 결과를 단계별로 저장하는 방법
- Selenium으로 동적 페이지를 크롤링할 때 `WebDriverWait`, 스크롤 처리, 난독화된 DOM 대응 방법
- `StreamingHttpResponse`(NDJSON)와 `fetch` 스트림으로 서버 진행 상황을 실시간 표시하는 방법
- 정규식 전처리, IQR(사분위 범위) 통계, LLM 프롬프트로 부적절 댓글을 분류·증강·요약하는 방법
- 크롤러·LLM 같은 외부 의존을 서비스 계층으로 분리하고 mock으로 테스트하는 방법

## 7. 느낀 점

- 사이트 구조가 바뀌기 쉬운 크롤링은 "한 번 되면 끝"이 아니라, 실패했을 때 원인을 바로 볼 수 있는 장치
  (단계별 오류 메시지, 실패 시 스크린샷 저장)가 중요하다는 것을 느꼈습니다.
- LLM 응답은 형식이 흔들리므로 JSON 파싱과 개수 검증을 방어적으로 해야 했고, 실패해도 서비스가
  멈추지 않게 설계하는 것이 중요했습니다.
- 기능이 돌아가는 것과 사용자가 보기 편한 것은 별개여서, 진행 단계 표시와 "제거된 댓글 흐리게 보기"처럼
  처리 과정을 보여주는 화면이 이해에 큰 도움이 된다는 것을 알게 되었습니다.
